# FLARE-VAX：基于 NHIS 2024 的行为理论引导流感疫苗接种预测

[English](README.md)

本项目研究 **Health Belief Model（HBM）是否能够为 LLM 的个体化疫苗接种判断提供稳定、可解释的行为结构**。数据来自 **2024 National Health Interview Survey（NHIS）Sample Adult**，目标变量为：

```text
SHTFLU12M_A：过去 12 个月是否接种流感疫苗
```

本周的主要工作不是继续叠加更多 numerical prior 或 residual model，而是进一步收缩研究问题：

> **先用 HBM 建立一个可解释的行为 anchor，再系统研究 HBM 在什么样的人群中会失败，以及 LLM 能否利用这些历史失败规律判断当前 respondent 是否应该偏离 HBM 的原始结论。**

---

## 1. 数据与 V4 / V5 设置

开发时使用的 NHIS Sample Adult 原始文件约包含 **32,629 名 respondent、630 个变量**。在 target 与 feature-policy 筛选后，主要实验使用约 32K respondent，并固定划分为：

```text
40% memory
20% calibration
40% test
```

V4 与 V5 的区别保持不变：

| Version | 设置 | 主要区别 |
|---|---|---|
| **V4** | 保留其他疫苗史 | 可使用 COVID-19、肺炎、带状疱疹、甲肝等 non-target vaccination history |
| **V5** | 去除其他疫苗史 | 所有 non-target vaccination-history variable 从 scoring、prompt、retrieval 和 memory construction 中排除 |

两者都先从 NHIS observable variables 构造五个 HBM-guided proxy，再形成：

```text
Motivation
Capability
Activation / Cue
```

并得到原始的 8 个 HBM behavioral patterns。

> 这里的 HBM quantity 是由 NHIS observable variables 构造的 theory-guided proxy，不是对个体私人信念的直接 psychometric measurement。

---

## 2. 早期 TFM-FLARE-VAX：保留为失败尝试，不再作为主方法

此前的 TFM-FLARE-VAX 尝试在原版 FLARE 的 `P_pattern` 之外进一步加入 theory-failure memory、contrastive retrieval 和 empirical Q-value，希望让 LLM 同时看到“通常遵循 HBM 的 historical cases”和“历史上明显偏离 HBM 的 cases”。

整体流程可以简化为：

```text
NHIS respondent
      ↓
HBM-derived profile
      ↓
HBM8 pattern + P_pattern
      ↓
ordinary memory + theory-failure memory
      ↓
reward / Q-guided contrastive retrieval
      ↓
LLM individualized integration
      ↓
P_final
```

这条路线的主要问题是结构较复杂，但增量效果并不稳定；同时 ordinary memory、failure memory、Q-value 和 residual adjustment 多个模块混在一起后，很难直接回答“HBM 到底为什么失败”。因此本周没有继续扩展这一版本，只保留它作为原版 FLARE 的一个探索性 extension，并把后续工作重新聚焦到 **HBM state 本身以及 state-specific theory failure**。

---

## 3. V82：从 HBM8 扩展到 HBM16

V82 是原版 FLARE 的直接拓展。最明显的变化是：**不再只使用 8 个粗粒度 behavioral pattern，而是在每个 HBM8 pattern 内根据额外的 theory-support intensity 再划分为 `Support-High / Support-Low`，形成 16 个 refined HBM states。**

具体来说，先保留原来的三维结构：

```text
Motivation: High / Low
Capability: High / Low
Cue: Strong / Weak
```

这三维组合形成 HBM8。随后在每个 HBM8 pattern 内，根据 memory split 中五个 theory-support proxy 的综合水平，进一步划分：

```text
Support-High
Support-Low
```

最终得到 HBM16。

### 3.1 HBM16 的 16 个类别

| ID | Motivation | Capability | Cue | Secondary support state |
|---|---|---|---|---|
| H01 | High | High | Strong | Support-High |
| H02 | High | High | Strong | Support-Low |
| H03 | High | High | Weak | Support-High |
| H04 | High | High | Weak | Support-Low |
| H05 | High | Low | Strong | Support-High |
| H06 | High | Low | Strong | Support-Low |
| H07 | High | Low | Weak | Support-High |
| H08 | High | Low | Weak | Support-Low |
| H09 | Low | High | Strong | Support-High |
| H10 | Low | High | Strong | Support-Low |
| H11 | Low | High | Weak | Support-High |
| H12 | Low | High | Weak | Support-Low |
| H13 | Low | Low | Strong | Support-High |
| H14 | Low | Low | Strong | Support-Low |
| H15 | Low | Low | Weak | Support-High |
| H16 | Low | Low | Weak | Support-Low |

HBM16 的作用不是建立一个新的黑盒 classifier，而是减少原来 HBM8 内部过度压缩的问题。例如两个 respondent 都属于 `High Motivation / High Capability / Strong Cue`，但如果一个人的五个 HBM support 整体很强、另一个明显较弱，他们不再被强制使用完全相同的 behavioral anchor。

### 3.2 V82 结果：原版 FLARE vs. HBM16 refinement

这里仅保留 **Llama 4 Scout 17B** 下最核心的对比：原版 FLARE-VAX 与 HBM16 refined anchor。

| Version | Method | Test N | Accuracy | Balanced Acc. | ROC-AUC | F1 |
|---|---|---:|---:|---:|---:|---:|
| V4 | Original FLARE-VAX + Scout | 12,853 | 0.7298 | 0.7312 | 0.7789 | 0.7174 |
| V4 | **V82 HBM16 refined anchor** | 12,837 | **0.7362** | **0.7342** | **0.8039** | 0.7144 |
| V5 | Original FLARE-VAX + Scout | 11,057 | 0.6101 | 0.6179 | 0.6334 | 0.6265 |
| V5 | **V82 HBM16 refined anchor** | 12,842 | **0.6495** | **0.6478** | **0.7046** | 0.6242 |

V82 的结果说明，**仅仅把 HBM8 进一步细分为 HBM16，就已经可以得到更有区分度的 behavioral anchor**。因此后续 V83 / V84 都不再回到 HBM8，而是把 HBM16 作为 theory baseline。

> 注：旧 V5 Scout full run 最终汇总了 11,057 个 successful test predictions，而 V82 HBM16 结果使用 12,842 个有效 test rows，因此这里主要用于展示方法演进方向，而不是严格 paired significance test。

## 4. V83 + V84：当前主体方法 —— 发现 HBM16 的失败规律，再由 LLM 判断是否应该偏离 HBM16

本周最核心的调整是把问题重新定义为：

> **HBM16 先给出 theory-guided baseline；然后我们研究在每一个 HBM16 state 内，什么样的额外 observed configuration 会让 HBM16 明显更容易失败；最后让 LLM 判断这些历史 failure pattern 是否真正适用于当前 respondent。**

因此当前方法不再试图直接训练一个新的 probability model 去替代 HBM16，而是把工作拆成两个清楚的阶段。

### 4.1 Stage 1：在每个 HBM16 state 内发现可重复的 failure subgroup

首先固定 HBM16 state。也就是说，我们不是把所有 HBM16 错误混在一起分析，而是在：

```text
同一个 HBM16 state 内
    HBM16 failure cases
        vs.
    same-state ordinary / correctly predicted cases
```

寻找额外的 observed feature pattern。

流程为：

```text
V82 HBM16 anchor
      ↓
按 HBM16 state 分组
      ↓
在 state 内扫描额外 feature / feature-pair condition
      ↓
比较 subgroup 的 HBM16 error rate
      ↓
memory split 发现候选规律
      ↓
calibration split 验证是否仍成立
      ↓
保留 stable strong error rules
```

这里的额外 feature 包括原始 NHIS observed variables，以及描述 HBM information compression / mismatch 的 deterministic descriptors。例如：

- age / chronic burden；
- healthcare access 与 utilization；
- preventive vs. acute healthcare contact；
- construct disagreement / support spread；
- V4 的 cross-vaccine behavior；
- V5 的 information / care-connected engagement；
- 以及其他在同一 HBM16 state 内仍可能区分 failure subgroup 的 raw profile feature。

一个 rule 只有在 **memory 和 calibration 两边都表现出较高 HBM16 error enrichment，并且 residual / failure direction 稳定** 时，才会进入下一步。Test split 不参与 rule discovery 和 rule selection。

### 4.2 从统计 rule 到 Card：让 LLM 理解“HBM16 为什么可能失效”

Stage 1 得到的原始结果通常是很多具体 condition，例如：

```text
feature A <= threshold
feature B == value
feature A + feature C pair
```

这些规则本身可以告诉我们某个 subgroup 的 error rate 较高，但它们还不是一个适合直接交给 LLM 的行为解释。因此 V84 增加第二层整理：**把同一 HBM16 state 内具有相似语义、相同 failure direction 的 verified rules 整理成 failure mechanism card。**

当前保留两种 card source：

**Default Card**：先由程序输出 verified strong rules，再由我离线逐 state 阅读这些结果并进行 semantic consolidation，形成固定 reference card。这里没有 Stage-1 API call。

**LLM-generated Card**：把同一批 verified strong rules交给 Scout，让 Scout 在每个 HBM16 state 内做 semantic consolidation。Python 只允许 LLM 负责 qualitative grouping，所有 error rate、residual、sample size 和 empirical probability 都重新从 verified rule 中挂回，LLM 不拥有 numerical authority。

所以两者真正比较的是：

```text
同一批 verified empirical rules
          ↓
Assistant offline consolidation
          vs.
Scout semantic consolidation
          ↓
完全相同的 frozen-card schema
```

### 4.3 Card 中保存什么

每个 failure mechanism card 主要包含：

```text
HBM16 state
failure mechanism / qualitative summary
representative empirical rule
representative rule 所需的 current feature values
memory / calibration HBM16 error rate
error lift
historical failure direction
P_pattern within subgroup
P_HBM16 within subgroup
empirical residual / delta
```

因此 card 不是“让 LLM 自由总结一些错误案例”，而是一个由 verified statistics 支撑的结构化 theory-failure evidence。

### 4.4 Test-time：只把真正可能属于 HBM16 failure pattern 的 case 交给 LLM

对新的 test respondent，系统首先正常计算：

```text
HBM16 state
+
P_HBM16
```

然后只在当前 respondent 真正匹配某个 verified representative rule，并且该 rule 在 calibration 中显示足够高的 HBM16 failure rate、且 historical failure direction 与当前 HBM16 decision 相冲突时，才把它视为一个 active failure-card case。

LLM 看到的核心信息为：

```text
current HBM16 state
P_HBM16
current matched feature values
matched failure mechanism
historical HBM16 error rate
historical failure direction
P_pattern / P_HBM16-within-pattern / empirical delta
```

然后 LLM 只需要回答：

```text
APPLY
REJECT
UNCERTAIN
```

含义是：

- `APPLY`：这个历史 HBM16 failure mechanism 对当前 respondent 也适用，应考虑偏离原 HBM16 prediction；
- `REJECT`：虽然当前 case 匹配统计 pattern，但更像一个例外，不应修改 HBM16；
- `UNCERTAIN`：证据不足，保留 HBM16。

LLM 不负责生成新的 error rate、confidence-weighted probability 或 residual model。V84 同时实现了 direct empirical correction 和 soft-gate post-processing；为了让 README 保持简洁，下面只报告 **direct empirical correction** 作为主结果。

### 4.5 V84 最终结果

下面只保留最终 LLM 方法，不再重复列出 HBM16 anchor、mechanical card 或 soft-gate ablation。

| Version | Test-time model | Card source | Test N | Accuracy | Balanced Acc. | ROC-AUC | F1 | Log Loss | Brier |
|---|---|---|---:|---:|---:|---:|---:|---:|---:|
| V4 | Llama 4 Scout 17B | Default Card | 12,852 | **0.7412** | **0.7408** | **0.8088** | **0.7285** | 0.5338 | 0.1780 |
| V5 | Llama 4 Scout 17B | Default Card | 12,852 | **0.6607** | **0.6619** | **0.7104** | **0.6566** | 0.6197 | 0.2155 |
| V4 | Llama 4 Scout 17B | Scout-generated Card | 12,852 | **0.7434** | **0.7437** | **0.8083** | **0.7345** | 0.5339 | 0.1780 |
| V5 | Llama 4 Scout 17B | Scout-generated Card | 12,852 | **0.6553** | **0.6582** | **0.7091** | **0.6622** | 0.6209 | 0.2161 |
| V4 | Llama 4 Maverick 17B | Default Card | 12,852 | **0.7404** | **0.7400** | **0.8087** | **0.7275** | 0.5340 | 0.1781 |
| V5 | Llama 4 Maverick 17B | Default Card | 12,852 | **0.6595** | **0.6601** | **0.7101** | **0.6515** | 0.6199 | 0.2156 |

当前结果说明：**HBM16 本身已经是一个较强的 theory anchor，而 state-specific failure analysis 可以在不替换 HBM16 的前提下进一步带来小幅但稳定的提升。** V4 中 Scout-generated Card 略优于 Default Card；V5 中 Default Card 更好。这也说明 semantic consolidation 本身不是越复杂越好，真正重要的是 verified subgroup evidence 与当前 case 是否匹配。

目前完成的正式结果包括：

```text
Scout + Default Card        → V4 / V5 complete
Scout + Scout-generated Card → V4 / V5 complete
Maverick + Default Card     → V4 / V5 complete
```

`Maverick + Scout-generated Card` 当前没有完成结果，因此不在表中补写或推测。

## 5. V86：进一步聚焦 “XGBoost 能救回、但 HBM16 失败” 的案例

V83 / V84 分析的是 **所有 HBM16 failure cases**。V86 保留完全相同的总体逻辑，但进一步收缩 Stage-1 的研究对象，只关注：

```text
HBM16 wrong
AND
fair raw-feature XGBoost correct
```

也就是说，V86 不再问“HBM16 在哪里容易失败”这一宽泛问题，而是问：**在什么样的 HBM16 state-specific subgroup 中，一个数据驱动的 raw-feature model 能够系统性地识别 HBM16 没有捕捉到的行为信息？** 后续仍然按照 memory discovery → calibration verification → semantic card consolidation → test-time LLM adjudication 的两阶段流程进行。XGBoost 在这里作为 rescue signal，而不是直接替代 HBM16 成为最终预测器。V86 的代码、V4/V5 Default Card 和 Scout-generated Card 实验框架已经完成，但正式 full-test 结果尚未跑完，因此本周 README 暂不报告 V86 metric。

## 6. 本周结论

本周的主要变化可以概括为三点：

1. **缩减旧方法。** 不再继续扩展复杂的 reward / residual / failure-router 路线，早期 TFM-FLARE 只保留为探索性尝试。
2. **把 HBM representation 从 HBM8 细化为 HBM16。** 结果显示更细粒度的 theory state 本身就能明显改善 anchor quality。
3. **把研究重点转向 theory failure。** 当前主体不是让另一个 ML 模型替代 HBM，而是让 HBM16 先定义行为状态，再通过 state-specific subgroup discovery 找出 HBM16 的稳定 failure pattern，最后让 LLM 判断这些 historical failure mechanism 是否应该应用到当前个体。

当前最核心的研究问题因此变成：

> **Can behavioral theory provide a useful default decision structure, while an LLM learns from verified historical theory failures to recognize when that structure should be overridden for a new individual?**
